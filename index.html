Deterministic Guard

AIエージェントの暴走・無限ループを防ぐ2つの終了条件

Exit = Success Exit ∨ Safety Exit （終了条件 ＝ 成功終了 または 安全遮断）
✓

Success Exit（成功終了）

外部ハーネス検証（Guard）の完全パス

  • ● Compile が正常に通る
  • ● Unit Test が全件パスする
  • ● Linter の警告・エラーがゼロ
  • ● 指定された成果物（Artifact）が物理的に存在する
Checkpoint Commit 実行 → Human Review
⚡

Safety Exit（安全遮断）

Progress Circuit Breaker による強制停止

  • ● 最大試行回数（max_retry）に到達
  • ● 同じエラーの連続反復（2回連続 no-progress）
  • ● 許可されていない対象外ファイルの無断変更
  • ● Context / Token / 実行時間の上限到達
強制 Cut & Return → Checkpoint Failed

Actual Trajectory Replay

Not “the AI said it works.”
The trajectory proved it.

Portable Agent does not treat a model response as success. It creates isolated work, lets the LLM inspect and modify the repository, measures the result with an external Guard, retries when necessary, and only then advances to an Accepted Checkpoint.

Isolated Worktree The human repository stays untouched while the agent works.
External Guard Success is measured outside the model.
Checkpoint Ownership The LLM may change artifacts. Portable Agent owns the commit transition.
Explicit Lifecycle Work is created, accepted, and closed as separate operations.

A real v0.5.0 end-to-end run

The sequence below is based on an actual Portable Agent run. The first attempt failed its Guard, the next attempt corrected the artifact, and only then did the trajectory reach Gate ACCEPT.

  1. 01 · Human Repository

    Start from a clean human-owned repository

    Portable Agent begins from the accepted human state. No agent execution occurs on the human branch.

    CLEAN 
    main
HEAD: f9a81f1
README.md:
# customer-system

  2. 02 · work create

    Create an isolated Agent Worktree

    Work gets its own agent/* branch and managed worktree.

    ISOLATED 
    $ portable-agent work create \
  --repo customer-system \
  --agent coder \
  --task step12-e2e

Work created
Branch:   agent/coder/step12-e2e/<run-id>
Worktree: worktrees/customer-system/coder/step12-e2e/<run-id>

  3. 03 · Search / Read / Implement

    Let the LLM investigate the repository

    The response-only API model uses Portable Agent's project tools to search, read, and modify only the managed worktree.

    Repository
   ↓ search
Relevant Artifact
   ↓ read

   ↓ apply_patch / write
dirty Artifact

    The model says “done.” The Guard says “not yet.”

    Model completion does not advance the trajectory. The externally executed Guard is authoritative.

    Retry from explicit external state

    The next attempt receives the current checkpoint, dirty artifact state, Guard failure, goal, and constraints — not an ever-growing chat history.

    The artifact is corrected and measured again
